# MCP 퇴원·학원비 정산 0.3.0

퇴원 처리와 선택한 청구의 취소·감액·실제 완료된 환불 기록을 같은 트랜잭션으로 적용한다. 이미 퇴원·졸업한 학생은 `student_settle` / `preview_student_settlement`로 추가 정산한다. 학생·교육원 소속 검사, 변경 전 해시와 행 잠금, 확인 키 재시도 멱등성을 유지한다.

퇴원 날짜만 보내면 청구·납부·미납 목록을 먼저 보여준다. 청구가 남아 있으면 `settlements` 또는 `billing_decision=preserve`라는 명시적 결정 없이 확인할 수 없다. 선택하지 않은 청구는 보존되며 미리보기에 유지할 청구 id와 정산 이후 총 미납액을 표시한다. 실제 학생에게 적용하려면 원장이 금액·대상을 확인해야 한다.

## 입력과 금액

- `cancel`: 납부액 0원의 선택 청구를 최종금액 0원 / cancelled로 바꾼다. 행을 삭제하지 않는다.
- `adjust`: 원장이 확인한 총 청구액 `final_amount`로 감액한다. 이미 받은 금액 아래로 줄일 때는 환불 정산이 필요하다. 남겨 둔 미납금은 기존 `payment_pay`로 수납할 수 있다.
- `refund`: `refund_amount`, `final_amount`, `refund_method`, `refund_completed=true`를 받는다. 실제 환불 완료가 확인된 뒤 순납부액을 줄이고 `expenses.category=refund` 지출과 별도 정산 이력을 기록한다. 이 도구는 송금·카드 취소를 실행하지 않는다. 법정 환불액을 날짜 비례로 추측하거나 자동 계산하지 않는다.
- 청구마다 `payment_id`, `reason`이 필수다. 중복 청구 선택·초과 환불·청구액 증가·미래 정산일은 거부한다.

원본 수입 행은 유지한다. 새 `max_engine_payment_settlements`에는 변경 전후 청구액·납부액, 감액·환불액, 지출 id·사유·처리자를 기록해 기존 납부 내역을 추적한다. 부분 납부를 통째로 삭제하지 않는다. 기존 `student_payments.refund_amount` 휴원 크레딧 필드는 다른 의미이므로 재사용하지 않는다.

일반 월 학원비와 청구·등록이 각 한 건으로 명확히 연결된 시즌 학원비를 지원한다. 시즌 납부액·취소 표시·환불액도 동일 트랜잭션에서 갱신하고 등록 행을 보존한다. 상품·기타 청구, 휴원 크레딧·선납 묶음, 불명확한 시즌 연결은 원본 정산 화면으로 안내한다. 시즌의 별도 등록·청구 생성, 문자·급여, 자동 금융기관 환불은 범위 밖이다.

## 검증과 적용

합성 데이터만 사용한 격리 MySQL 실라우트 테스트와 단위 테스트 51건(Node18), loopback OAuth/MCP 15건(Node22), lint·구문·diff 검사 통과. 납부/수입 보존, 교육원 격리, 실제 완료 환불 입력 강제, 동일 확인 재시도, 원본 변경 거부, 정산 및 출결 실패의 전체 롤백을 검증했다. 핵심 3파일 coverage statements96.19%, branches90.72%, functions/lines100%. 근거 `mcp-settlement-20261004/verification.json`.

배포 후보 19개 파일 기준 운영 해시 일치·신규 경로 부재를 확인했다. 배포 직전 다시 비교해 다르면 중단한다. PACA 코드·DB와 MCP 현재 릴리스/포인터·OAuth를 서버에서 백업하고 검증한 뒤 additive 정산 audit DDL을 적용한다. PACA 후보만 교체하고 현재 MCP 릴리스를 복사해 후보만 덮어쓴다. PACA 및 두 MCP를 재시작한 후 health·인증된 실제 도구 목록·새 명령 미리보기를 검증한다. 실학생 confirm은 호출하지 않는다. 롤백은 후보 파일·포인터 복원이며 이미 존재하는 청구·정산 기록·OAuth를 덤프로 덮어쓰지 않는다. audit table은 운영 롤백에서도 보존한다. PACA 웹 4.0.56은 변경이 없어 별도 프론트 배포하지 않는다.
