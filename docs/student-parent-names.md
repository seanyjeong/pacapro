# 학생 보호자 성함

PC 학생 등록·수정 화면의 **보호자 정보**에 아버지·어머니 성함을 각각 선택 입력한다.
기존 학부모 전화번호는 같은 영역에 배치한다. 공용 PC 폼은 창이 좁으면 한 열, 넓으면 두 열이며
입력칸 높이는 최소 44px, 칸 사이 여백은 20px 이상이다.

PC 학생 상세의 연락처 아래에는 아버지·어머니 성함 항목을 항상 표시한다. 저장된 성함이
없으면 `미입력`으로 표시하고 **보호자 정보 입력**을 누르면 수정 화면의 해당 입력칸으로
바로 이동한다. 성함이 있으면 같은 자리에서 **보호자 정보 수정**을 선택할 수 있다.

PC 학생 목록과 수납 목록은 학생 이름뿐 아니라 부모님 성함으로 검색할 수 있다.
성함의 공백과 영문 대소문자는 검색에 영향을 주지 않는다. 목록에 별도 열을 늘리는 대신
학생 정보 아래에 보호자 성함을 표시하고 긴 이름은 줄바꿈한다.
형제자매처럼 같은 이름이 여러 학생에게 등록돼 있으면 모두 표시한다.
납부 대상과 금액은 사용자가 확인한 학생·결제 ID를 사용하며 이름으로 자동 배정하지 않는다.

이번 기능은 PC 학생정보와 수납 화면 대상이다. `/m`·`/tablet` 전용 화면의 보호자 성함 표시와
결제 검색 확장은 제외한다. 공용 결제 목록은 PC 화면에서만 명시적으로 성함 표시를 활성화한다.

## 저장과 호환성

- `students.father_name`, `students.mother_name`: nullable `VARCHAR(512)`, 기존 AES-256-GCM 키 사용.
- 입력은 각 100자까지, 양끝 공백 제거. 빈 문자열·null은 삭제, 필드 생략은 기존 값 보존.
- 자료형 오류·제어문자·암호문 형태의 입력은 400 응답. 암호화 실패 시 평문을 저장하지 않는다.
- 기존 학생은 기본값 null이며 금액·수업 일정 계산은 변경하지 않는다.
- 기존 학원 경계와 학생 수정·결제 조회 권한을 유지한다. 감사 로그에는 성함 원문을 남기지 않는다.
- 휴원·복귀의 기존 작업 응답에서는 신규 개인정보 필드를 제외한다. 최신 보호자 정보는 학생 상세 API로 조회한다.

## 배포 순서와 복구

1. 운영 학생 테이블 백업과 기존 키 설정 상태를 확인한다. 키나 학생 개인정보를 로그에 출력하지 않는다.
2. `backend/migrations/20260914_add_student_parent_names.mysql`을 적용한다.
   두 열을 테이블 끝에 `ALGORITHM=INSTANT`로 추가하며 재실행할 수 있다.
   기존 열이 있다면 nullable, 길이 512, 기본값 null인지 확인한다. 다른 정의라면 임의 변경하지 않는다.
3. 백엔드 배포 후 학생 조회와 결제 조회를 확인하고 프론트엔드를 배포한다.
   **이 기능은 DB 변경을 포함하므로 프론트엔드만 먼저 배포하지 않는다.**
4. 문제 발생 시 이전 앱 버전으로 복구하되 신규 열은 남겨 입력된 정보를 보존한다.
   `.down.mysql`은 별도 백업 후 명시적으로 데이터를 폐기할 때만 사용하는 수동 절차다.

## 재현 검증

```sh
node --test test/student-parent-names.test.mjs
python3 scripts/release/test-student-parent-names-mysql.py
npm run build
PACA_SMOKE_BASE_URL=http://localhost:3112 node scripts/smoke/student-parent-names-smoke.mjs
cd backend
npm run test:ci -- --runInBand
```

MySQL 검증은 소켓 전용 임시 DB를 만들고 종료 시 제거한다. 운영 DB·실제 학생 자료는 사용하지 않는다.
브라우저 검증은 학생·부모님 이름과 결제 API를 모두 가상 데이터로 처리하며 운영 수납을 변경하지 않는다.

## 2026-09-14 검증 결과

- 백엔드 135개 스위트, 1,154개 테스트 통과. 기본 실행에서 생략되는 DB 테스트는 별도로 실행했다.
- 전체 재실행 중 기존 알림 설정 테스트가 한 차례 실패했으며, 해당 파일 단독 및 전체 재실행에서 통과를 확인했다.
- 실제 임시 MySQL: 신규 보호자 정보 5건, 기존 수납·취소·출결 계약 7건 통과.
- 프론트 이름 검색 단위 테스트 2건, PC 기능과 모바일 전용 화면 제외를 검증하는 브라우저 시나리오 10건 통과.
- 기존 학생 등록·수정, 학생 목록, 데스크톱 결제, 태블릿 결제, 모바일 미납 스모크 통과.
- 프로덕션 빌드 및 타입 검사 통과. 린트 오류 0건(기존 경고 82건). 신규 UI 디자인 검사 지적 없음.
- 변경 런타임 파일은 모두 500줄 이하. 앱 버전 4.0.51.

운영 DB 적용·GitHub 푸시·운영 배포는 이 검증에 포함하지 않았다.

모바일 범위 정정 후 공용 결제 목록의 PC 성함 표시, 모바일·태블릿 성함 미표시,
기존 이름 검색·단건 납부를 재검증했다. 프로덕션 빌드·타입 검사·린트와
모바일 미납·태블릿 결제 회귀 스모크를 다시 통과했다. 백엔드는 이전 검증 결과를 재사용했다.
