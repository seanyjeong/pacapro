# 선행반 입시유형

## 도메인 결정

- `student_type`은 기존처럼 `exam`(입시생)을 사용한다.
- 선행반은 별도 수강료나 반 테이블이 아니라 학생의 현재 `admission_type=advance`로 저장한다.
- 녹취에서 요청한 단일 입시유형 모델을 따른다. 선행반 지정 전의 정시·수시 값은 별도로 보존하지 않는다.
- 선행반 대상 학년은 중1~중3, 고1~고2다. 고3 또는 N수로 이동하면 `regular`(정시)로 전환한다.

## 적용 경로

- 학생 생성·수정·엑셀 가져오기
- 학생 목록 필터·배지·상세 표시·엑셀 내보내기
- 수동 일괄 진급과 정기 자동 진급
- 학생 유형을 성인으로 바꿨다가 입시생으로 되돌려도 기존 선행반 선택을 복원한다.

## 의도적으로 변경하지 않는 경로

- `classes.admission_type`: 현재 프론트엔드 소비자가 없는 별도 반 관리 도메인이다.
- 수업료, 학생별 수업요일, 시즌비, SMS 학년 그룹: 기존 `student_type`, `grade`, `class_days` 규칙을 유지한다. 따라서 SMS의 중등부·고등부 수신자 구분은 선행반 배지가 아니라 기존 학년 기준으로 표시된다.
- 상담의 `admission_type`: 학생 프로필과 별도인 상담 전형 데이터다.

## 배포와 롤백

1. 운영 DB 백업과 `students.admission_type` 정의를 확인한다.
2. `20260826_add_advance_student_admission_type.mysql`을 먼저 적용한다.
3. 백엔드와 프론트엔드를 순서대로 배포한다.
4. 롤백 시 코드를 먼저 되돌리고, 스키마 축소가 꼭 필요할 때만 `advance` 행을 `regular`로 치환한 뒤 ENUM을 축소한다.
