# 시즌 종료 후 무료 수업과 자동 졸업

시즌 설정에는 기존 `season_end_date`와 별도로 `free_lesson_end_date`(무료 수업 종료일), `post_free_action`(종료 후 처리)이 있다. 신규 시즌은 두 필드를 반드시 설정해야 한다. 무료 수업 종료일은 시즌 종료일보다 빠를 수 없고, 같은 날로 지정하면 추가 무료 기간 없이 다음 날 처리한다. 기존 시즌은 두 필드가 `NULL`이므로 설정하기 전까지 종전 동작을 유지한다.

- `graduate`: 무료 수업 종료일 **다음 날 00:00 KST**에 활성·휴원 학생을 자동 졸업 처리한다. 월 청구는 00:01 KST에 실행되며, 그 직전에 졸업 처리를 한 번 더 확인한다. 졸업 처리 오류가 나면 월 청구 전체를 중단한다.
- `regular`: 무료 수업 종료일까지 월 청구를 막고, 그 다음 달부터 재원 학생의 월 청구를 허용한다.
- 두 설정이 없는 기존 시즌: 월 청구와 학생 상태 처리에 변화가 없다.

무료 수업은 시즌이 끝난 뒤 시작한다. 그 기간의 자동·일괄·개별 월 청구와 휴원 복귀 시 월 청구는 제외되며, 이미 납부한 청구나 시즌비는 수정하지 않는다. `graduate` 설정의 처리가 지연된 동안에도 새 월 청구를 막는다. 다른 시즌에 재등록한 학생은 이전 시즌의 자동 졸업 대상에서 제외한다. 새 시즌이 시작된 달부터는 이전 시즌의 무료 기간·졸업 대기로 인한 월 청구 차단을 해제하고 새 시즌 월납부 정책을 따른다. 졸업 시 학생 상태와 현재 시즌 표식만 바꾸고, 시즌 등록 이력과 기존 납부/미납 기록은 보존한다. 적용 시각은 `student_seasons.aftercare_applied_at`에 남긴다. 이후 담당자가 학생을 다시 재원 처리하면 이전 졸업 설정이 새 월 청구를 계속 막지 않는다.

운영 적용 순서: `seasons`와 `student_seasons`를 각각 백업하고 행 수·복원 가능성을 확인한 뒤 `backend/migrations/20261001_add_season_aftercare.mysql`을 적용한다. 새 컬럼 정의와 기존 행의 `NULL` 보존을 확인하고 백엔드를 배포한다. 이후 학원별 시즌 설정에서 무료 수업 종료일과 처리 방법을 저장하고, 프론트엔드 4.0.56을 배포해 설정·상세 화면을 확인한다. 코드 롤백 시에는 기존 시즌의 설정값을 되돌린 뒤 이전 코드를 다시 배포하고, 추가된 DB 컬럼은 보존한다. 운영 DB 변경과 배포는 별도 승인된 출시 절차에서만 한다.

일산 `26-27수시`의 요청값은 **무료 수업 종료일 2026-11-30, 종료 후 자동 졸업**이다. 2026-10-01 12:55 KST 운영 DB 읽기 전용 확인: 일산 학원 ID 2, 시즌 ID 3, 시즌 종료일 2026-10-30, 등록 17명(재원 16명·기졸업 1명), 이후 시즌 재등록 0명, 이 등록자들의 2026년 10~12월 청구 0건, 새 DB 컬럼 0개였다. 이 기능의 설정만으로 기존 시즌 종료일을 바꾸지 않는다. 운영 반영 직전 이 수치와 청구 상태를 다시 확인하고 차이가 있으면 중단한다. 11월 30일까지는 자동 졸업하지 않고, 12월 1일 청구 생성 전에 대상자를 졸업해야 한다.

검증: 시즌 생성·수정 API의 유효성 검사, 월 청구 순서·실패 시 중단, 개별 청구 차단, KST 졸업 스케줄을 Jest로 확인한다. 일회용 MySQL 8 환경에서 9월 30일 종료·11월 30일 무료 종료 사례를 시험해 10·11월 청구 제외, 11월 30일 졸업 0건, 12월 1일 졸업 2건, 재실행 0건, 타 시즌 재등록자 제외, 재원 유지 선택의 무료 기간 후 청구 재개를 확인했다. 운영 데이터는 이 격리 시험에 사용하지 않았다.
