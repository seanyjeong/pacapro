# 파카 지점·반 + 맥스엔진 지점별 연결 — 설계 (초안)

- 작성: 2026-11-12
- 상태: 사장님 검토 대기 (구현 전)
- 근거: 대구 원장 통화(2026-11-12), 파카 `origin/main` c705072 조사, 맥스엔진 `main` c851c2c2 조사

## 1. 목표

파카 학원 계정 하나 안에 **지점 → 반** 두 단계를 두고, 맥스엔진 교육원 계정 여러 개가 같은 파카 학원에 **자기 지점 학생만** 연결되게 한다.

대구 예시:

| 파카 (계정 1개: 대구) | 맥스엔진 계정 |
|---|---|
| 지점 마산, 상인성서 | 건모 |
| 지점 수성 | 나문 |
| 지점 칠곡, 복현 | 동인 |

각 지점 아래에 정시반·수시반·선행반·주말반 같은 반이 붙는다.

### 수용 기준
1. 지점·반을 하나도 안 만든 학원은 화면·API·자동 배정·엔진 동기화가 지금과 똑같다.
2. 학생을 지점·반에 넣고 옮길 수 있고, 학생 목록에서 지점·반으로 걸러 인원수와 명단이 나온다. 엑셀 첫 칸에 지점·반이 나온다.
3. 출석 화면에서 반을 고르면 요일과 상관없이 그 반 명단 전체가 뜨고, 그 자리에서 체크한다(보강 포함).
4. 엔진 계정 3개가 같은 파카 학원에 연결되고, 각자 자기 지점 학생만 받는다.
5. 학생이 지점을 옮겨도 엔진에서 "삭제됨"으로 처리되지 않는다.

### 제외
- 반별 수업료·시간표 (수업료는 지금처럼 학생별)
- 지점별 권한 분리 (같은 학원 원장·관리자는 지금처럼 전부 봄)
- 지점별 회계·매출 집계
- 피크(실기) 쪽 지점 구분 — 대구가 피크를 어떻게 쓸지 정해진 뒤 별도

## 2. 파카 데이터

### 새 테이블 `branches` (지점)
`id, academy_id, name, sort_order, status(active/inactive), created_at, updated_at`
- `UNIQUE(academy_id, name)`

### 기존 테이블 `classes` (반) — 재사용
- 지금 전 학원 0건이고 화면에 연결된 적이 없다 (`backend/paca.js` 의 `ROUTE_EXCLUDE` 로 라우트도 꺼져 있음).
- 추가: `branch_id` (필수), `sort_order`
- 그대로 씀: `class_name`, `default_time_slot`, `status`, `description`
- 안 씀(그대로 둠): `class_type`, `grade`, `admission_type` — 학생 쪽 값과 겹침

### `students` 에 칸 2개 추가
- `branch_id` (NULL 허용) — 지점
- `class_id` (NULL 허용) — 반. 값이 있으면 그 반의 지점과 `branch_id` 가 같아야 한다.

학생에 직접 칸을 두는 이유:
- 한 학생 = 한 반이라 연결 테이블이 필요 없다.
- 지점을 옮기면 `students.updated_at` 이 바뀌어 엔진 증분 동기화가 놓치지 않는다. 연결 테이블이면 놓친다.
- 반 없이 지점만 있는 학생이 가능하다. 엔진에서 새로 등록한 학생이 이 상태로 들어온다.

`student_classes` 테이블은 쓰지 않고 그대로 둔다(삭제는 별도 정리).

### 켜고 끄기
- 따로 스위치를 두지 않는다. **지점이 1개 이상 있는 학원 = 지점·반 사용 학원.**
- 지점이 없으면 관련 필터·칸·메뉴가 화면에 나오지 않는다.
- 설정 화면에서 언제든 지점·반을 만들면 그때부터 켜진다.

### 마이그레이션
- `backend/migrations/20261112_add_branches_and_student_class.mysql` + down 파일
- 기존 방식대로 `information_schema` 확인 후 `ALGORITHM=INSTANT` 칸 추가, 백업 뒤 수동 적용
- `__tests__/integration/max-engine-schema.json`, `maxEngineReadCatalog.json` 갱신

## 3. 파카 기능

### 3-1. 설정: 지점·반 관리
- `/paca/branches` 한 곳에서 지점·반·학생 배정을 다룬다 (`routes/branches.js`). 기존 `routes/classes.js` 는 꺼진 채 그대로 둔다(안 쓰는 옛 코드, 정리는 별도).
- 학생이 있는 지점·반은 삭제 대신 비활성
- 반을 다른 지점으로 옮기면 그 반 학생의 `branch_id` 도 같이 바꾼다

### 3-2. 학생
- 신규 등록 화면과 학생 상세 화면에 지점·반 선택 (지점 사용 학원만). 학생 저장 API 는 건드리지 않고 배정 API(`PUT /paca/branches/students`)를 따로 부른다.
- 목록: 지점·반 필터, 반별 인원수, 지점·반 칸 (`routes/students/crud/list.js`, `student-filters.tsx`, `student-list-table.tsx`)
- 여러 명 골라 한 번에 반 이동
- 엑셀: 첫 칸에 지점·반 (`routes/exports/students.js`)

### 3-3. 출석 — 반 명단 모드
- 지금 구조(날짜+시간대마다 수업 1개, 요일로 자동 배정)는 건드리지 않는다. 같은 조회·생성 코드가 12곳에 있어 바꾸면 위험이 크다.
- 새 조회 `GET /paca/schedules/class-roster?date&class_id[&time_slot]`
  - 그 반 학생 전원 + 그 날짜·시간대의 출석 상태를 돌려준다
  - 시간대를 안 주면 반의 기본 시간대
- 체크하면 기존 출석 저장(`POST /paca/schedules/:id/attendance`)을 그대로 쓴다. 그날 배정이 없던 학생은 출석 행을 새로 만든다 — 지금 "학생 추가"와 같은 길.
- 모바일·태블릿·PC 출석 화면에 "반으로 보기"를 추가. 지점 없는 학원에는 안 보인다.
- 매월 자동 배정은 지금처럼 수업 요일이 있는 학생만. 요일을 안 넣은 학생은 반 명단 모드로만 체크한다.

### 3-4. 문자
- 발송 대상에 지점·반 필터 (`routes/sms.js`, `routes/sms/auxiliary.js`, `all-recipient-filters.tsx`)

## 4. 맥스엔진 연결

### 지금
- 엔진 교육원 1 ↔ 파카 학원 1. 엔진 DB `branch_external_links` 의 `UNIQUE(provider, external_academy_id)` 와 코드(`repo.occupied`)가 둘 다 막는다.
- 파카 토큰에는 학원 번호만 있다. 학생 자료에 지점 칸이 없다.
- 엔진은 하루 한 번 전체를 읽고, 거기 없는 연결 학생을 삭제로 본다.

### 바꾸는 것 — 파카 쪽
1. **토큰에 지점 범위.** `/paca/integrations/max-engine/token`, `/full/token` 이 `branch_ids` 를 받아 검증(그 학원의 지점인지)하고 토큰 claim 에 넣는다. 응답에 그 학원의 지점 목록을 준다.
2. **범위 없는 토큰 = 학원 전체.** 지금 연결된 학원은 아무것도 안 바뀐다.
3. **범위 필터.** 범위가 있으면 학생이 걸리는 모든 읽기·쓰기에 `students.branch_id IN (범위)` 를 건다.
   - 동기화·스냅샷: `maxEngineSyncRepository`, `maxEngineRepository`
   - 일반 읽기: `maxEngineFullReadRepository.read()` 한 곳 (자원 144개 중 학생이 걸린 22개 + 학생 자체)
   - 업무 조회 5개: `maxEngineWorkflow*.js`
   - 쓰기: `maxEngineFullCommandRepository.row()`·`roster`, 일정·수업 저장소
4. **학생 자료에 지점·반 추가.** `branch_id, branch_name, class_id, class_name`
5. **범위 밖으로 나간 학생 알림.** 증분 동기화에서 "지난번 이후 바뀌었고 지금은 범위 밖"인 학생을 번호와 `out_of_scope` 표시만 넣어 준다. 삭제 확인 응답도 "삭제"와 "범위 밖"을 구분한다.
6. **엔진에서 학생 등록(`student_create`).** 연결 범위의 지점 중 하나를 받는다. 범위가 1개면 자동, 여러 개면 엔진 화면에서 고른다.

### 바꾸는 것 — 엔진 쪽
1. **연결 제약 완화.** 새 테이블 `branch_external_scopes(provider, external_academy_id, external_branch_id, branch_id)` + `UNIQUE(provider, external_academy_id, external_branch_id)`.
   - 한 파카 지점은 엔진 교육원 하나에만 붙는다.
   - 범위 없는 연결은 지금처럼 학원 통째로 하나만.
   - `branch_external_links` 의 학원 단위 유일 제약은 풀고, 겹침 검사를 코드로 옮긴다.
2. **연결 화면.** 파카가 준 지점 목록에서 내 지점을 고른다.
3. **동기화.**
   - 토큰 요청마다 지점 범위를 보낸다.
   - `out_of_scope` 학생은 삭제가 아니라 **연결만 푼다.**
   - 다른 엔진 교육원에 이미 연결된 파카 학생이 내 범위로 들어오면 → **엔진 학생을 내 교육원으로 옮긴다**(성적·상담 기록 유지). 10분마다 제약 오류가 나는 것을 막는다. (확인 필요 ①)
4. **학원 번호로 찾는 곳 점검.** 문자, 시즌(DL), 피크 실기 연결. 시즌은 학원 공통이라 그대로, 문자는 발신 설정이 학원 공통이라 그대로, 피크는 이번 범위에서 제외하되 깨지지 않는지만 확인.
5. 계약 문서 갱신: `docs/contracts/paca-sync.md`, 결정 기록 `docs/06-decisions.md`, 상태 `docs/11-status.md`

### 배포 순서 (서로 안 깨지게)
1. 파카 먼저. 범위 없는 요청은 지금과 같으므로 엔진이 옛 코드여도 문제없다.
2. 엔진 다음. 지점 범위를 안 고른 교육원은 지금과 같다.
3. 대구만 새 방식으로 연결.

## 5. 단계

| 단계 | 내용 | 운영 영향 |
|---|---|---|
| 1 | 파카 지점·반 기본: DB, 설정 화면, 학생 배정·이동, 목록 필터·인원수, 엑셀 | 지점 없는 학원은 변화 없음 |
| 2 | 파카 반 명단 출석, 문자 필터 | 위와 같음 |
| 3 | 엔진 연결: 파카 계약 → 엔진 | 범위 없는 연결은 변화 없음. 동기화 경로를 건드리므로 가장 조심 |
| 4 | 대구 이관: 아카 명부 엑셀 일괄 등록, 엔진 계정 3개 재연결 | 대구만 |

- 1·2단계는 덧붙이는 변경이라 시즌 중에도 배포할 수 있다.
- 3단계는 일산 등 기존 연결이 쓰는 동기화 코드를 고친다. 통합 테스트(일회용 MySQL / 엔진 Postgres)로 "범위 없는 연결은 결과가 한 글자도 안 바뀐다"를 먼저 고정한다.
- 대구는 이번 시즌 3계정 그대로, 4단계는 시즌 뒤.
