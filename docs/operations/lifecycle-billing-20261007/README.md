# 휴원·퇴원 청구 정산 수정 — 2026-10-07

배포 대상은 Vultr `/root/pacapro/backend`, `paca-failover.service`의 백엔드 4.0.22다. 프론트 4.0.57과 MCP 0.4.1의 코드·서비스는 이번 배포 대상에 포함하지 않는다.

## 수정한 동작

- 퇴원 버튼과 일반 학생 상태 변경에서 같은 정산 서비스를 사용한다. 전액 미납 청구는 행을 남기고 취소한다. 부분 납부 청구는 이미 납부한 금액과 수입 이력을 보존하면서 남은 미납 잔액만 면제한다. 납부 완료 청구는 그대로 남는다.
- 일반 학생 수정의 휴원 처리에서 존재하지 않는 `payments` 조회를 제거했다. 전용 휴원 처리와 동일하게 휴원 시작월의 모든 미납 월 청구를 시작일 전날까지 달력 일할로 조정한다. 천 원 미만은 절삭하고 이미 납부한 금액보다 청구액을 낮추지 않는다.
- 학생 행을 잠그고 상태·청구·정산 감사·수업 배정 변경을 같은 연결과 트랜잭션에서 처리한다. 중간 실패는 전체를 롤백한다. 날짜를 쓰기 전에 검증한다.
- 청구에 일할 원금과 계산 내역을 남긴다. MySQL JSON 키 정규화와 관계없이 동일 휴원 요청은 중복 감액·감사행·크레딧을 생성하지 않는다.
- 시즌 종료는 실제 스키마의 `is_cancelled`, `cancellation_date`, `after_season_action`을 사용한다. 시즌 납부액과 환불 기록은 보존한다.
- 환불 실행은 하지 않는다. 전용 휴원 화면의 명시적 이월/환불 크레딧 기능을 유지한다. 이번 배포에서 기존 학생·청구를 일괄 소급 변경하거나 실제 학생 처리 API를 호출하지 않는다.

첫 통합 실행에서 새 휴원 조회 SQL의 예약어 `year_month` 인용 누락 때문에 5개 휴원 시나리오가 실패했다. 이를 고친 뒤 새 native suite 16개가 모두 통과했다. 같은 실행에서 통과한 기존 MCP suite 40개는 변경된 모듈을 사용하지 않아 해당 근거를 재사용했다. 첫 실패 로그도 보존한다.

## 적용과 복구

`deploy.py`는 변경 대상 11파일의 운영 원본 SHA-256/신규 파일 부재를 확인하고, 기존 정산 스키마와 실제 systemd 실행 경로를 확인한다. 운영 백업 후 교체 직전에 원본과 환경 파일을 재확인한다. 차이가 생기면 교체 전에 중단한다.

운영 DB는 `mysqldump --single-transaction`으로 백업하고 gzip 무결성을 검사한다. 코드와 환경 파일은 서버의 0700 백업 디렉터리에 보존한다. 이번 변경에는 스키마 migration이나 의존성 설치가 없다.

실패하면 변경한 코드만 복구하고 PACA를 재시작한다. DB를 덮어쓰지 않는다. 되돌리기 태그는 `rollback/paca-lifecycle-billing-20261007`이며 운영 적용 결과와 백업 경로는 `deployment-result.json`에 기록한다.

운영 확인은 내부/외부 health, systemd active, 설치 소스 해시, 실제 backend/package.json 버전, 세 학생 처리 경로의 무인증 401을 사용한다. 이는 실학생 퇴원·휴원 실행 검증을 의미하지 않는다.
