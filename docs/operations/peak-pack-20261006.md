# PEAK MCP 운동팩 생성·저장 — 2026-10-06

승인 범위는 기존 운동 라이브러리에서 운동을 선택해 순서대로 새 팩에 저장하는 기능과 MCP 버전업·운영 반영이다. `preview_exercise_pack_create`에서 이름·설명·운동 id 배열을 받고, 원장이 미리보기를 승인한 후 기존 `confirm_change`로 저장한다. MCP 후보 버전은 0.4.1이며 PEAK 19개/PACA 28개 도구다. 조회 72종·변경 31종 중 새 변경은 `peak_exercise_pack_create`다.

실제 PEAK `exercise_packs` 및 `exercise_pack_items` 테이블을 사용한다. 스냅샷은 앱과 같은 `peak-exercise-pack` 형식·버전 1.0이며 운동 이름·태그·기본 세트/횟수·설명·영상 링크와 순서를 담는다. 팩 자체 버전 1.0은 MCP 서버 버전 0.4.1과 별개다. 실제 SQL 반환 순서와 관계없이 요청한 운동 id 순서대로 스냅샷 및 연결의 display_order를 저장한다. 원본 운동 라이브러리는 보존된다.

서버가 교육원·활성 작성자·선택 운동의 소유 범위를 검사한다. 내 교육원 및 academy_id NULL 공유 운동만 허용하며 외부 운동은 404다. 내 교육원의 같은 이름 팩은 409, 빈/중복/잘못된 id 및 위조 author/snapshot은 422다. 운동 1~200개만 받는다. 태그 메타데이터는 선택 운동이 참조하는 활성 내 교육원/공유 태그만 포함한다. 작성자 이름은 클라이언트가 보내지 않고 인증 계정 원본을 복호화한다.

미리보기는 쓰기 0건이다. 확인 시 선택 운동·태그·작성자·동명 팩의 변경을 다시 검사하며 바뀌면 SOURCE_CHANGED 409를 반환한다. 교육원 잠금과 팩·연결·명령 이력을 하나의 PEAK 트랜잭션에 넣어 중간 실패를 모두 되돌린다. 같은 미리보기 재확인은 기존 멱등 응답을 반환한다. 기존 팩 교체·라이브러리 적용·실제 고객 팩 생성은 이번 작업에서 실행하지 않는다.

검증 근거와 실제 배포 결과는 같은 이름 디렉터리에 보존한다. 신규 unit 및 인증 HTTP/MySQL 시험은 실제 운영 스키마의 메타데이터를 사용한 합성 fixture로만 실행한다. MCP SDK 시험은 실제 OAuth/도구 호출 경로와 모의 원본 서버를 사용하며 운영 고객 확인 호출은 하지 않는다.
