# 학생 휴원 복귀 크레딧 재계산

## API

`POST /paca/students/:id/resume`

인증된 원장·관리자가 휴원 학생을 복귀 처리한다. 요청 본문은 `resume_date`
(`YYYY-MM-DD`)를 선택적으로 받으며, 생략하면 한국 날짜 기준 오늘을 사용한다.

## 크레딧 규칙

- 휴식 인정 마지막 날은 복귀일의 전날이다.
- 크레딧은 휴식 시작월 안에서만 계산한다.
- 명시한 휴식 종료일이 있으면 그 날짜보다 늘리지 않는다.
- 월 수강료를 해당 월의 달력 일수로 나눈 뒤 실제 휴식일을 곱하고 1,000원 단위로 절삭한다.
- 미사용 크레딧은 금액과 잔액을 함께 조정한다.
- 일부 사용 크레딧은 사용액을 보존하고 새 정상 금액에서 사용액을 뺀 금액을 잔액으로 둔다.
- 휴원 뒤 월 수강료가 바뀌어 기존 크레딧의 계산 기준과 맞지 않으면 자동 변경하지 않는다.
- 이미 사용한 금액이 새 정상 금액보다 크거나 같은 휴식 회차에 자동 크레딧이 여러 건이면 복귀 전체를 취소하고 확인 안내를 반환한다.
- 수동 크레딧과 다른 학원·학생·휴식 회차의 크레딧은 변경하지 않는다.

크레딧 재계산, 복귀월 청구 생성/조정, 출결 배정, 학생 상태 변경을 **같은 연결의
단일 트랜잭션**으로 처리한다. 하나라도 실패하면 모두 되돌려 휴원 상태에서 재시도할 수 있다.
학생 행 잠금으로 같은 학생의 중복 복귀 요청을 직렬화한다.

## 학생 수정 화면

휴원 상태인 학생에게 `휴원 복귀` 버튼을 표시한다. 기존 공용 복귀 모달에서
“며칠에 복귀하시겠습니까?”라고 묻고 선택한 날짜를 위 API의 `resume_date`로 보낸다.
휴원 시작일 이후의 과거/현재/미래 날짜를 선택할 수 있다. 미래 날짜도 예약이 아니라
즉시 재원 전환이며, 해당 복귀월의 복귀일부터 말일까지 출결을 배정한다.
요일별 시간대와 이미 존재하는 출결은 보존한다.

재원 선택지는 비활성화한다. 일반 학생 수정 API로 `paused → active`를 요청해도
409 `RESUME_REQUIRED`로 거부한다. 다른 프로필 수정은 유지한다.
복귀 처리는 저장된 정보 기준이므로 미저장 수정 사항은 먼저 저장하도록 안내한다.
휴원 중 프로필 저장은 이미 축소된 청구를 월정액으로 덮어쓰지 않는다.
복귀 후 학생·청구·스케줄 캐시를 갱신하고 수정 폼의 상태도 재원으로 다시 불러온다.
모달은 수정 form 밖에 두어 복귀 클릭으로 일반 수정이 함께 제출되지 않게 한다.

## 같은 달 휴원·복귀 청구

- 복귀월 청구가 없으면 기존 정책대로 수업 요일 / 주 횟수 × 4 기준의 일할 청구를 생성한다.
- 월 전체 청구가 남아 있으면 중복 청구하지 않는다. 휴원 크레딧은 실제 휴원 기간으로 재계산한다.
- 같은 달 `process-rest`가 축소한 청구는 휴원 전 출석 가능 일수와 복귀일~말일을 합산한다.
  휴원 때 적용한 **달력 일수 기준**을 유지하고 천원 단위로 절삭한다.
  예: 31만원, 10/11 휴원, 10/21 복귀 → 10만원 청구를 21만원으로 조정한다.
- 부분 납부 때문에 휴원 당시 청구가 납부액까지로만 줄어든 경우도 같은 합산액을 사용한다.
  납부액을 다시 더하지 않으며, 납부액/기존 크레딧 적용 내역/납부기한은 변경하지 않는다.
  조정된 청구는 `is_prorated=1`로 표시해 일반 학생 수정에서 월정액으로 덮어쓰지 않게 한다.
- 기존 청구가 여러 건이거나, 축소 청구에 휴원 크레딧/이월 사용이 겹치거나,
  원래 청구 구성 금액으로 기존 휴원 축소 산식을 재현할 수 없으면 409로 전체 복귀를 취소한다.
  과거 휴원 처리에 원금 스냅샷/조정 표식이 없어 임의 수동 조정과 확정적으로 구별할 수는 없다.
  해당 사례와 반복 휴원처럼 산식이 맞지 않는 사례는 정산 내역 확인이 필요하다.
- 다른 달의 기존 청구는 유지한다.

`paymentAdjusted`는 기존 청구를 조정했을 때 `{id, yearMonth, previousAmount, finalAmount}`이며
그 외에는 `null`이다. 신규 청구는 종전처럼 `paymentCreated`로 반환한다.

## 성공 응답 추가 필드

`creditRecalculation`은 관련 자동 크레딧이 없으면 `null`이다. 관련 크레딧이
있으면 아래 정보를 반환한다.

```json
{
  "adjusted": true,
  "creditId": 12,
  "creditType": "carryover",
  "previousAmount": 258000,
  "creditAmount": 103000,
  "remainingAmount": 103000,
  "usedAmount": 0,
  "restStartDate": "2026-08-12",
  "restEndDate": "2026-08-19",
  "restDays": 8,
  "status": "pending"
}
```

기존 `message`, `student`, `scheduleAssigned`, `paymentCreated`, `resumeDate`
필드는 유지한다.

## 확인이 필요한 경우

자동 재계산으로 회계 정합성을 보장할 수 없으면
`REST_CREDIT_RECALCULATION_CONFLICT`와 한국어 안내를 반환하고 학생 상태와
크레딧을 모두 원래대로 되돌린다. 화면에는 상태 코드나 내부 오류 대신 해당
확인 안내만 표시한다.
