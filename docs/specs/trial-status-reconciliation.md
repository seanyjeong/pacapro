# 체험생 상태 재계산 규칙

체험생 상태는 `trial_dates`의 오늘 이후 미출석 일정에서 계산한다. 브라우저가 보내는
`trial_remaining` 값은 신뢰하지 않으며, 서버가 같은 일정 배열에서 남은 횟수와 상태를 함께 결정한다.

## 상태 규칙

- 오늘 또는 이후의 미출석 일정이 1개 이상이면 `status=trial`, `is_trial=true`이다.
- 남은 일정이 없으면 `status=pending`, `is_trial=false`, `trial_remaining=0`이다.
- 과거의 미출석 일정은 체험 잔여 횟수에 포함하지 않는다.
- 미등록 학생을 다시 체험생으로 등록할 때는 오늘 또는 이후의 새 일정을 반드시 입력한다.
- `status=trial` 또는 숫자형 `is_trial=1` 요청도 같은 새 일정 검증을 통과해야 한다.
- 체험생을 미등록·재원 등 비체험 상태로 바꾸면 `is_trial=false`, `trial_remaining=0`을 함께 저장한다.
- 마지막 체험 출석을 저장하면 같은 트랜잭션에서 즉시 상태를 재계산한다.
- 과거 출석을 취소해도 이미 만료된 학생을 체험 상태로 되살리지 않는다.

매일 00:05 KST 작업은 누락된 상태를 정리하는 안전망이다. 정상 흐름은 학생 생성·수정,
상담의 체험 전환, 출석 저장 시점에 같은 공통 규칙을 사용한다.
